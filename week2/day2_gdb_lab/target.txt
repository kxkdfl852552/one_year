## 第二周第二天：gdb 调试基础

### 1. -g 是干什么的？

`-g` 用来生成调试信息。

有了 `-g`，gdb 才能看到源码行号、函数名、变量名等信息。

如果不加 `-g`，程序也能运行，但是 gdb 调试时信息会少很多。

### 2. -O0 为什么适合调试？

`-O0` 表示关闭编译优化。

调试时关闭优化，可以让源码行和程序执行过程更一致，变量也不容易被编译器优化掉。

如果使用高优化等级，比如 `-O2` 或 `-O3`，gdb 里可能出现变量看不到、执行顺序和源码不一致的情况。

### 3. gdb 里的 bt 是什么？

`bt` 是 `backtrace` 的缩写，用来查看调用栈。

调用栈可以告诉我们程序崩溃前经过了哪些函数。

例如：

`main -> run -> get_value`

如果程序在 `get_value` 里崩溃，`bt` 可以帮助我们快速找到问题路径。

### 4. 程序崩溃时怎么找是哪一行？

先用 gdb 启动程序：

`gdb ./crash`

然后运行：

`run`

程序崩溃后，使用：

`bt`

查看调用栈。

再用：

`frame 0`

切换到崩溃现场。

然后用：

`list`

查看源码。

最后用：

`print 变量名`

检查关键变量的值。

### 5. next 和 step 区别是什么？

`next` 是执行下一行，但不进入函数内部。

`step` 是执行下一行，如果这一行有函数调用，就会进入函数内部。

例如当前代码是：

`run();`

使用 `next` 会直接执行完整个 `run()`。

使用 `step` 会进入 `run()` 函数里面继续调试。
